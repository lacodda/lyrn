# ADR 0007: A form that adds to a repository never replaces a file

- Status: accepted
- Date: 2026-09-23

## Context

Every form before `docs` starts a repository, and its one guard is that the
destination is empty or absent. The `docs` form is the first that writes into
a tree it did not make: a repository that exists, has history, and - when lyrn
made it - already has a `docs/` directory holding `docs/adr/`.

"Empty or absent" means nothing there. The obvious replacement, skipping the
files that exist and writing the rest, is the worst available: a repository
with its own `docs/package.json` would get an Astro config beside a manifest
that does not install Astro, and the site would half-exist.

## Decision

A form declares its **placement**: a new directory, or into an existing one.
For the second:

- The destination must exist. The default is the directory lyrn is run in,
  not a new one named after the project.
- The whole plan is checked before anything is written. If any file it would
  write is already there, **nothing** is written, and every one of them is
  named in the error - not only the first.
- A repository that already has a documentation site of another kind (mdBook,
  MkDocs, Docusaurus, VitePress, Sphinx, Jekyll, Astro) is refused the same
  way. Two sites would be two truths about one product.
- A dry run makes the same checks, so it never promises files the real run
  would refuse.

And for every form, a file is **created, never replaced**: the writer opens
each file with `create_new`. The check above says whether the way is clear;
this makes an overwrite impossible rather than merely checked for, including a
file that appears between the check and the write.

The site's own checks - the address, and the Markdown twins for agents - are
Astro integrations inside the generated project, run on every build. lyrn's
own documentation site builds with the same two files, held byte for byte by a
test, so each build of this site is a live run of what the form hands out.

## Consequences

- The next additive work - `lyrn adopt`, and add-ons applied to an existing
  project - inherits the placement and the create-only writer instead of
  inventing a guard of its own.
- The form writes no `lyrn.toml`: a repository generated by lyrn has one
  already, and writing it would be exactly the replacement this decision
  forbids. Recording that a project has docs belongs to `lyrn adopt`.
- A refused run costs the user a list of files to move aside. That is cheaper
  than any merge lyrn could guess at.
